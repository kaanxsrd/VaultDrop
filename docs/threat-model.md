# Threat model

Assets: secret plaintext (highest), link keys and passphrases, receipt tokens, API keys, session cookies, account data, and metadata about who shared what with whom.

Trust boundaries: sender's browser/CLI → TLS-terminating proxy → VaultDrop app → PostgreSQL / Redis / SMTP / Stripe → recipient's browser.

| Threat                              | Mitigation (implemented)                                                                                                                                     | Residual risk                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------- |
| Database or backup disclosure       | Only ciphertext + verifier stored; keys live in URL fragments; payloads deleted on consume/expire/burn                                                       | Metadata exposed; residual ciphertext in WAL/backups until recycled (unreadable without keys) |
| Network interception                | HTTPS required (HSTS header); keys never sent in requests                                                                                                    | TLS misconfiguration at the operator's proxy                                                  |
| Secret enumeration                  | 128-bit random ids; redemption needs 256-bit-derived proof; per-IP and per-secret rate limits                                                                | —                                                                                             |
| Passphrase brute force              | Argon2id; per-secret 10/min limit; destroy after N failures (default 10)                                                                                     | Weak passphrase + leaked link + DB dump enables offline guessing                              |
| Replay of a redeem request          | One-time state transition; replay gets 410                                                                                                                   | —                                                                                             |
| Race conditions / double redemption | `SELECT … FOR UPDATE` + conditional `UPDATE … WHERE state='active' AND view_count=?`; tested with 25 concurrent requests and 2,000-request load races        | —                                                                                             |
| Interrupted redemption              | Claim and payload deletion are one transaction; rollback on any error leaves the secret active; failure _after_ commit loses the secret (fail closed)        | Recipient may need a new link if the response is lost after commit                            |
| XSS                                 | Per-request nonce CSP with `strict-dynamic`; no third-party scripts; React escaping; no `dangerouslySetInnerHTML`                                            | `style-src 'unsafe-inline'` is allowed for inline style attributes                            |
| CSRF                                | SameSite=Lax cookies; Origin / Sec-Fetch-Site checks on cookie-authenticated mutations; Better Auth origin checks; server actions have Next.js origin checks | —                                                                                             |
| Clickjacking                        | `frame-ancestors 'none'`, `X-Frame-Options: DENY`                                                                                                            | —                                                                                             |
| Referrer / cache leakage            | `Referrer-Policy: no-referrer`; `Cache-Control: no-store` and `X-Robots-Tag: noindex` on /s, /receipt, /dashboard, /admin and all API responses              | —                                                                                             |
| Link-preview bots consuming secrets | Status lookups never consume; redemption requires an explicit click plus a key-derived proof                                                                 | —                                                                                             |
| Session compromise                  | HTTP-only cookies, 7-day expiry, session list with remote revocation, password change revokes other sessions, optional TOTP and passkeys                     | —                                                                                             |
| Account brute force                 | Better Auth rate limits (5 sign-ins/min), Argon2id password hashing, generic error messages                                                                  | Better Auth's limiter is per instance (memory)                                                |
| Accidental logging                  | Pino redaction of sensitive keys at any depth; URL paths logged with ids replaced and without query/fragment; no request bodies logged; tested               | Third-party proxies may log full URLs (fragments are never sent)                              |
| Insider access                      | No admin capability to view payloads or restore destroyed secrets; ciphertext is undecryptable without links                                                 | Insider could tamper with served JS (see "malicious server")                                  |
| Malicious or compromised server     | CSP limits injected scripts; CLI provides an independent client                                                                                              | A fully compromised origin can serve malicious JS to browser users                            |
| Abuse of anonymous creation         | Per-IP creation limits; payload size caps; expiry caps                                                                                                       | Distributed abuse across many IPs                                                             |
| SSRF via webhooks                   | https only, credentials rejected, DNS-resolved private/loopback/link-local ranges blocked at creation and delivery, no redirects followed, 10s timeout       | DNS rebinding between check and connect                                                       |
| API key leakage                     | Hashed at rest, shown once, scoped, expirable, revocable, live/test separation                                                                               | —                                                                                             |
| Tenant isolation failures           | Ownership checks in every query path; "not yours" is indistinguishable from "not found"; tested                                                              | —                                                                                             |
| Billing spoofing                    | Plan changes only from signature-verified Stripe webhooks                                                                                                    | —                                                                                             |

Out of scope: endpoint malware, screenshots, social engineering of recipients, a compromised operator infrastructure.
